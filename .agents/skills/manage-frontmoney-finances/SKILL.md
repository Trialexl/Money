# FrontMoney: личные финансы через MCP

Работать с данными пользователя только через предметные инструменты подключенного OAuth MCP-сервера `frontmoney`. Инструменты сами определяют внутренний маршрут, HTTP-метод и авторизацию.

## Использовать MCP

- Для кошельков использовать `list_wallets`, `get_wallet` и `get_all_wallet_balances`.
- Для доходов, расходов и переводов использовать `list_transactions`, `get_transaction`, `create_transaction`, `update_transaction` и `delete_transaction`.
- Для планирования использовать `list_budgets`, `list_auto_payments`, `list_projects`, инструменты создания/изменения и инструменты графиков.
- Для аналитики использовать `get_dashboard`, `get_financial_report` и `get_financial_register`.
- Для инвестиций использовать `get_investment_records`, `list_investment_operations`, `get_portfolio_analysis`, `list_market_data` и соответствующие инструменты изменений.
- Не использовать shell, HTTP-клиенты, API-токены или переменные `FRONTMONEY_API_TOKEN` и `FRONTMONEY_BASE_URL`.
- Не просить пользователя присылать секреты. При ошибке OAuth сообщить, что нужно выбрать **Authenticate** у MCP `frontmoney` или выполнить `codex mcp login frontmoney`.
- Не передавать MCP пути, URL или HTTP-методы. Выбирать инструмент по финансовому действию и использовать его схему аргументов.

## Следовать рабочему процессу

1. Преобразовать относительные даты в конкретные даты `YYYY-MM-DD` по часовому поясу пользователя. В ответе назвать получившийся период явно.
2. Получить связанную сущность предметным инструментом чтения: кошелек, статью движения, портфель, счет или инструмент. Не угадывать UUID по названию.
3. Перед созданием финансовой записи проверить возможный дубль по дате, сумме, кошельку/счету и назначению.
4. Выполнить запрошенную операцию. Явная просьба «добавь», «измени» или «заполни» разрешает соответствующую одиночную запись.
5. После создания или изменения перечитать результат предметным инструментом чтения и кратко сообщить итоговые значения.

## Ограничить риск

- Для `DELETE`, массового изменения, замены графиков, backfill, refresh или генерации серии записей сначала показать точный scope и запросить подтверждение.
- Не вызывать инструменты создания, изменения или удаления, если пользователь просил только анализ, расчет, список или прогноз.
- Не исправлять существующие финансовые данные попутно без явной просьбы.
- Перед переводом проверить разные исходный и целевой кошельки, валюту и достаточность данных о сумме.
- Перед инвестиционной операцией проверить счет, инструмент, тип операции, количество, цену, комиссию, валюту и дату.
- Денежные суммы и цены передавать JSON-строками с десятичной точкой, не вычислять их через binary float.
- Не считать рыночные даты календарными: для отсутствующей цены сначала проверить торговый день и существующие записи, затем предложить refresh или backfill.
- Не давать инвестиционных гарантий. Отделять фактические данные портфеля от оценки или рекомендации.

## Выбрать домен

- Текущие деньги: кошельки, поступления, расходы, переводы, остатки.
- Планирование: бюджеты, статьи движения, регулярные платежи, проекты и графики.
- Аналитика: dashboard, движение средств, бюджетные и cash-flow отчеты.
- Инвестиции: счета, инструменты, операции, портфели, позиции, доходность, целевые доли, цены и FX.

## Ответить пользователю

Для чтения кратко указать период, валюту и ключевые итоги. Для изменения указать тип записи, дату, сумму или количество, связанную сущность и ID результата. При частичном успехе отделить выполненные записи от ошибок и не повторять успешные `POST` автоматически.
